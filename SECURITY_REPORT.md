# Безопасность: меры и оставшиеся риски

## Реализовано

- API keys читаются из окружения/`.env`; `.env` исключен через `.gitignore`, ключи не логируются.
- CORS ограничен origin из `CORS_ORIGINS`, по умолчанию `http://localhost:8000`; credentials не разрешены.
- Pydantic ограничивает длину сообщения и диапазон top-k; backend отдельно применяет `MAX_MESSAGE_LENGTH`.
- Ответы и ошибки внешнего API не содержат секретов; клиенту возвращаются обобщенные ошибки подключения.
- FAISS metadata хранится в JSON без pickle-десериализации.
- Frontend отображает пользовательские тексты через `textContent`, а не HTML-интерпретацию.
- Промпт запрещает модели следовать инструкциям из документов и требует использовать только найденные факты.

## Остаточные риски / production work

- SQLite хранит текст обращений открытым текстом. Нужны политика хранения/удаления и защита диска/резервных копий.
- Аутентификация, авторизация, rate limiting и защита от злоупотребления публичным API не включены.
- CORS не заменяет контроль доступа; для публикации приложения необходимы TLS и подходящий reverse proxy.
- Prompt injection и ошибочные ответы генеративной модели полностью исключить нельзя; требуется эксплуатационный мониторинг и оценка качества.
- Индекс и metadata должны обновляться согласованно; обновление двух файлов не является атомарной транзакцией.
- Совместимость и ограничения ProxyAPI embeddings зависят от выбранного endpoint и должны быть проверены владельцем credentials.
