### ⚠️ **Выявленные проблемы**

| № | Категория | Серьёзность | Описание | Рекомендация |
|---|-----------|-------------|----------|--------------|
| 1 | **Безопасность конфигурации** | ВЫСОКАЯ | Файл `.env` **не включён в `.gitignore`** — риск утечки секретов в систему контроля версий | Немедленно добавить `.env` в `.gitignore` |
| 2 | **Хранение пароля администратора** | СРЕДНЯЯ | `ADMIN_PASSWORD` хранится в открытом виде в `.env` | Хешировать пароль при хранении; использовать `werkzeug.security.generate_password_hash` |
| 3 | **Заголовки безопасности** | СРЕДНЯЯ | Нет явных заголовков безопасности (CSP, HSTS, X-Frame-Options и др.) | Добавить **Flask-Talisman** для автоматического управления заголовками безопасности |
| 4 | **Ограничение частоты запросов** | СРЕДНЯЯ | Нет ограничения частоты запросов на публичных конечных точках (форма обратной связи, вход) | Реализовать Flask-Limiter для `/contact`, `/admin/login` |
| 5 | **Защита от перебора паролей** | СРЕДНЯЯ | Вход в админ-панель не защищён от блокировки после неудачных попыток | Добавить отслеживание неудачных попыток + блокировку после N неудач |
| 6 | **Политика безопасности контента** | НИЗКАЯ | Нет заголовка CSP | Определить строгий CSP через Flask-Talisman |
| 7 | **Безопасность сессий** | НИЗКАЯ | Настройки cookie сессий не явно усилены | Установить `SESSION_COOKIE_SECURE=True`, `SESSION_COOKIE_HTTPONLY=True`, `SESSION_COOKIE_SAMESITE='Lax'` в конфиге |
| 8 | **Обработка ошибок** | НИЗКАЯ | Режим отладки управляется через `FLASK_DEBUG` — убедиться, что в production стоит `0` | Проверить `FLASK_DEBUG=0` в production `.env` |

### 🔧 **Рекомендуемые действия по исправлению**

#### Немедленные (перед развёртыванием в production)
1. **Добавить `.env` в `.gitignore`**
   ```gitignore
   # Файлы окружения
   .env
   .env.*
   !.env.example
   ```

2. **Установить и настроить Flask-Talisman**
   ```python
   # extensions.py
   from flask_talisman import Talisman
   talisman = Talisman()
   
   # app_factory.py
   talisman.init_app(app, 
       content_security_policy={
           'default-src': "'self'",
           'style-src': "'self' 'unsafe-inline' https://cdn.jsdelivr.net",
           'script-src': "'self' https://cdn.jsdelivr.net",
           'img-src': "'self' data:",
       },
       force_https=True  # Только при наличии HTTPS-прокси
   )
   ```

3. **Усилить настройки cookie сессий в `config.py`**
   ```python
   SESSION_COOKIE_SECURE = True      # Только через HTTPS
   SESSION_COOKIE_HTTPONLY = True    # Недоступно из JavaScript
   SESSION_COOKIE_SAMESITE = 'Lax'   # Защита от CSRF
   PERMANENT_SESSION_LIFETIME = timedelta(hours=12)
   ```

4. **Хешировать пароль администратора при хранении**
   ```python
   # В seed_admin(): хранить хеш, а не открытый текст
   from werkzeug.security import generate_password_hash
   user.password_hash = generate_password_hash(password)
   ```

#### Краткосрочные (в течение одного спринта)
5. **Добавить Flask-Limiter** для ограничения частоты запросов на `/contact` и `/admin/login`
6. **Реализовать защиту от перебора** на входе в админ-панель (отслеживание неудачных попыток по IP/пользователю)
7. **Добавить логирование событий безопасности** (успешный/неудачный вход, изменение пароля)

#### Долгосрочные (технический долг)
8. **Аудит заголовков безопасности** через `securityheaders.com` или Mozilla Observatory
9. **Сканирование зависимостей** — добавить `pip-audit` или `safety` в CI-пайплайн
10. **Пенетрационное тестирование** — запланировать ежегодную стороннюю проверку

## Заключение

**Общий уровень риска: СРЕДНИЙ**

Приложение следует лучшим практикам безопасности Flask для использования ORM, защиты от CSRF и экранирования шаблонов. Основные риски связаны с **управлением конфигурацией** (`.env` не в gitignore) и **отсутствием дополнительных уровней защиты** (заголовки безопасности, ограничение частоты запросов, защита от перебора).

**Приоритетное исправление:** Немедленно добавить `.env` в `.gitignore`, чтобы предотвратить случайную утечку секретов.
